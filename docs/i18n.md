# Language switch and text convention (DE / EN)

BoreholeHub is German by default. The DE | EN switch in the header changes the UI to English.
This page describes the switch and the text convention. Later pages are translated the same way.

## 1. The switch and the cookie

- The switch is a form in `nav.site-nav` (`Pages/Shared/_Layout.cshtml`). It posts to `/Sprache`
  with the antiforgery token, a hidden `returnUrl` (current path and query string) and `lang` = `de` or `en`.
  It works without JavaScript. Each button has `lang` and `aria-label` ("Deutsch" / "English").
- `/Sprache` sets the cookie `bh-lang`: `Path=/`, 365 days, `SameSite=Lax`, `HttpOnly`, `IsEssential=true`,
  `Secure` when the request is HTTPS. The value holds only the UI language (`uic=de-DE` or `uic=en`).
- The redirect goes to `returnUrl` only if `Url.IsLocalUrl` accepts it, otherwise to `/`. Any `lang` other than `de` or `en` gives 400.
  A GET to `/Sprache` redirects to `/`.
- `Program.cs` reads only this cookie. It ignores the browser language and query strings.
- `<html lang>` follows the UI culture (`de` or `en`).

### Only the UI language changes

The culture stays `de-DE` in both languages, so number and date formats are always German
(decimal comma, `dd.MM.yyyy`). Form input, CSV import and the PDF report behave the same in both modes.

### What stays German

- Norm codes: DIN 4023, BM-0 to BM-F3, KRB, DPH, F1 to F3 (D119).
- The PDF report "Anlagen" (D119) and the German `Meldung` texts it uses.
- Demo data (F-S12-2: formats and data are not translated).
- The footer version "Version 1.0.0" until a version decision is made (F-S12-3).

## 2. Resource files and the path rule

German is the key. There are no `.de.resx` files: a missing English entry shows the German text.
English values live in `.en.resx` files under `src/BoreholeHub.Web/Resources/`. The path follows the code location.

| Kind of text | Code | Resource file | Access |
|---|---|---|---|
| Shared (layout, footer, texts used by several pages) | `SharedResource` (`SharedResource.cs`) | `Resources/SharedResource.en.resx` | `IStringLocalizer<SharedResource>` as `T` |
| Text in a view `Pages/<Folder>/<Name>.cshtml` | the view | `Resources/Pages/<Folder>/<Name>.en.resx` | `IViewLocalizer` as `L` |
| Text in a page model or other class `BoreholeHub.Web.<Namespace>.<Class>` | the class | `Resources/<Namespace>/<Class>.en.resx` | `IStringLocalizer<Class>` |

Example, shared text:
```cshtml
@inject Microsoft.Extensions.Localization.IStringLocalizer<BoreholeHub.Web.SharedResource> T
<a href="/Projekte">@T["Projekte"]</a>
<!-- Resources/SharedResource.en.resx: <data name="Projekte"><value>Projects</value></data> -->
```
Example, view text:
```cshtml
@inject Microsoft.AspNetCore.Mvc.Localization.IViewLocalizer L
<h1>@L["Seite nicht gefunden"]</h1>
<!-- Resources/Pages/NotFound.en.resx: name "Seite nicht gefunden", value "Page not found" -->
```
Example, class text (`BoreholeHub.Web.Pages.NotFoundModel`):
```csharp
public class NotFoundModel(IStringLocalizer<NotFoundModel> localizer) : PageModel { /* localizer["..."].Value */ }
// Resources/Pages/NotFoundModel.en.resx (namespace BoreholeHub.Web.Pages, class NotFoundModel)
```

### (a) Additions

- Format arguments: the German text with `{0}` is the key: `@L["Projekt {0} gespeichert", name]`. The English value has the same `{0}`.
- A text used by several pages goes to `SharedResource`, never into two page files.
- Partials map to their own path: `Pages/Shared/_ProjektTabs.cshtml` uses `Resources/Pages/Shared/_ProjektTabs.en.resx`.
- Keys are exact German texts, including punctuation and `·`. Do not reword a key.

### (b) Page-model messages (TempData, ModelState)

Store the German key and its arguments, never translated text. Localize when the message is shown.
```csharp
TempData["Status"] = "Projekt {0} gespeichert"; // German key
TempData["StatusArg"] = projekt.Name;          // argument, not translated
Status = _localizer[(string)TempData["Status"]!, TempData["StatusArg"]!].Value; // in the next request
```
Validation messages (ModelState, data annotations) are localized the same way, at the point of display.

### (c) SVG drawings in static C# classes

Static classes cannot take an `IStringLocalizer<T>` from DI (for example `BohrprofilSvg`, `RammdiagrammSvg`, `ProfilschnittSvg`, `DrawingLayout`).
The calling page model passes its own localizer as a parameter. The keys live in that page model's `.en.resx`.
```csharp
// Page model: var svg = BohrprofilSvg.Render(data, _localizer);   // _localizer = IStringLocalizer<BohrprofilModel>
// Drawing:    sb.Append(Escape(loc["Tiefe [m]"].Value));            // loc = the passed localizer, Escape = the existing helper
// Numbers stay German: value.ToString("0.0", new CultureInfo("de-DE"))
```

### (d) Messages from BoreholeHub.Core (Proposed, confirm in the task that translates Core messages)

Core has no ASP.NET dependency and gets no resx and no new package. Core exposes the German template and its arguments
next to the existing German `Meldung`, which stays German for the PDF. The Web layer localizes template and arguments.
```csharp
// Core (proposed): throw new DomainException("Zeile {0} fehlt", row);  // German template + arguments
// Web (proposed):  var text = _localizer[ex.Template, ex.Args].Value;   // localized in the Web layer
// The PDF keeps the German Meldung unchanged.
```

### (e) JavaScript

No translated text inside `.js` files. The Razor page renders each text as a `data-` attribute, and the script reads it.
The script may keep the German text as fallback.
```cshtml
<button id="delete" data-confirm="@L["Projekt wirklich löschen?"]">@L["Löschen"]</button>
```
```js
var text = button.getAttribute("data-confirm") || "Projekt wirklich löschen?"; // German fallback
if (window.confirm(text)) { /* ... */ }
```

## 3. Translator checklist

Go through every page for these, not only the visible text:
- text nodes and headings
- `<title>`, which comes from `ViewData["Title"]` and must be a plain string (`L[...].Value`)
- `aria-label`, `title` attributes and tooltips
- `placeholder`, `alt`
- button `value` and option texts in `<select>`
- validation messages (ModelState, data annotations)
- `confirm()` and `alert()` strings in JavaScript (via `data-` attributes, section 2 (e))
- SVG labels in drawings (section 2 (c))

## 4. Html.Raw

Never use `Html.Raw` for resource text. The footer is the only exception (plain text, no `<` or `&`).
Razor encodes the middle dot as `&#183;`, so the footer uses `@Html.Raw(T[...])` to keep the German bytes unchanged.

## 5. How to add a page

1. Write the page in German. Use `@inject IViewLocalizer L` and `L["<German text>"]` for each text.
2. Create `Resources/Pages/<Folder>/<Name>.en.resx` with one `<data>` entry per key (copy the header of an existing file).
3. Add a test that renders the page with the cookie and checks the English text (section 6).
4. `LocalizationCoverageTests` then checks the keys automatically.

Only the layout and the NotFound page are translated so far. Other pages stay German in English mode until their own task.

## 6. Tests

- `tests/BoreholeHub.Tests/LanguageSwitchTests.cs`: the switch, the cookie, 400 and redirect rules, NotFound in English, German decimal format in English mode.
- `tests/BoreholeHub.Tests/LanguageTestHelper.cs`: `CreateEnglishClientAsync(factory)` returns a client with the cookie set through the real `POST /Sprache`.
  Use `_factory.CreateClient()` for German. The helper does not follow redirects.
- `tests/BoreholeHub.Tests/LocalizationCoverageTests.cs` (generic, for all later pages):
  1. Every key in every `Resources/**/*.en.resx` appears as an exact quoted literal in a source file: `.cshtml` or `.cs` for page and class resources, any non-resx file for `SharedResource`. Build folders are skipped.
  2. Every `L["..."]` in a view that injects `IViewLocalizer` has an entry in the matching `.en.resx`.
  3. Every `T["..."]` in a view that uses `SharedResource` has an entry in `SharedResource.en.resx`.
- Example-only keys: the key `Beispieltext aus einer C#-Klasse` (class example, `NotFoundModel.en.resx`) is not used by any UI text.
  It is listed in `ExampleOnlyKeys` in `LocalizationCoverageTests.cs`. Do not add other example-only keys without adding them there and here.
